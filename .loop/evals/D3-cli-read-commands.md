eval: D3-cli-read-commands

**Rewritten 2026-07-31** against the operator's command-surface decision, then
corrected the same day after the plan review. The first version scored eight
commands, **seven** of which were `vault`, `nomad` and `consul` subcommands
mirroring native CLI calls (`nomad jobs`, `nomad job <id>`, `vault mounts`,
`vault policies`, `vault policy <name>`, `vault kv`, `consul services`). Those
are cut. The cockpit does not restate what `vault kv list` and `nomad job
status` already do; it does what no native CLI can, which is synthesize across
Vault, Nomad, Consul and the edge.

Several rows carry over unchanged, because they were never about which
commands exist: the `api/` purity contract, the no-subprocess rule, the
`vault grants` correctness rows, the offline suite and the read-only
guardrail all still bite.

**Definition of Done:** four read-only synthesis commands, split into a
`cli/src/localstack_cli/api/` layer that imports neither typer nor rich and a
`cli/src/localstack_cli/commands/` layer that renders it. Paths are D1's
(`.loop/plans/D1-cli-package-skeleton.md`, code surface). Seven rows below pass on
**no match**, and a grep over a path D1 never created returns no match too, so
the wrong prefix would pass all seven for the wrong reason. Every one of those
rows therefore asserts the directory exists first. Every `grep -E` pattern
below uses bare `|` for alternation: in an extended regex `\|` is a literal
pipe, so the escaped form can never match and the row can never fail.

Calls go over the HTTP APIs with `httpx`, never `subprocess`. Table by
default, `--json` everywhere, and a failure path that distinguishes "not
logged in" from "not allowed".

**Three verified facts drive most of these rows.** With a brokered
`nomad/creds/deploy` token, `GET /v1/jobs` returns **403**: the role withholds
`list-jobs` deliberately (`nomad_deploy_role.tf:4-5`). With a brokered
`consul/creds/deploy` token, `GET /v1/catalog/services` returns **2 of 25
services**, while the same call with **no token returns all 25**, and no error
fires either way. And the human Vault token carries only `default`
(`auth_userpass.tf:24-36` sets `token_policies = []`), which grants neither
`sys/policies/acl/*` nor `secret/metadata/*`, so `vault grants` and
`secret <service>` are denied their inputs until F7 lands.

**Scoring against the denials.** Every row below is scored against
respx-mocked servers, so a missing live grant never decides a row. The rows
that score a denial (rows 18 and 19) score the *message*, which is the
artifact that tells the operator which grant is missing.

**The trap.** A table that renders is not a table that is true. Rows 2, 3 and
14 exist because the natural implementation of `status`, `service` and
`vault grants` all produce confident, well-formatted, wrong output.
