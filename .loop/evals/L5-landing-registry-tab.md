# Eval: L5 registry tab on dash

eval: L5-landing-registry-tab

**Definition of Done:** dash gains a models/images tab strip that reads the
cluster registry over its plain HTTP API, renders each ModelKit's own
`README.md` as its model card, shows a pushed image as a row within one
sweep, keeps every byte of it behind oauth2-proxy, and does all of that
without touching a weights layer, raising dash's resource reservations, or
blocking the event loop.

| Behavior | Input | Expected | Fails-when | Scorer | Threshold |
|----------|-------|----------|------------|--------|-----------|
| An operator opens dash and reads a model's card without leaving the page | Signed-in browser, click the `embeddinggemma-q8` kit card | Modal shows the rendered `README.md` as HTML with its tables and fenced code intact, then the layers table, then the command list | The card pane renders raw markdown source, or is empty while the kit has a docs layer | Human + rubric (1-5 on fidelity to `assets/registry-mockup.html`) | 4/5 |
| A kit with no docs layer still shows its metadata | A manifest with no `application/vnd.kitops.modelkit.docs.v1.tar` layer | Route returns 200; the kit appears with Kitfile metadata and layers; the card pane says no card is present | The route raises, 500s, or omits the kit entirely | Deterministic (`test_registry.py`) | 100% |
| Each kit is drawn once even though two tags point at it | Live catalog: all four repos carry `0.1.0` and `latest` on one digest | Four kits in `models`, each listing both tags; four distinct digests; blobs fetched once per digest, not once per tag | A repo-tag walk that yields eight kits, or eight blob fetch pairs | Deterministic (`respx` call counts) | 100% |
| A newly pushed model appears without a page reload | Push a new tag, then wait one sweep interval with the tab open | The kit appears in the payload within one sweep; no restart, no manual reload | A new digest that never appears until the process restarts | Deterministic (`test_registry_client.py`, fixture sweep) | 100% |
| A pushed container image renders as a row | An image manifest whose config mediaType is an OCI image config | Row in `images` carrying repository, tag, digest, arch, size and pushed date; never routed to `models` | An image repo silently dropped, or classified as a ModelKit | Deterministic (`respx` fixture) | 100% |
| A multi-arch image is shown honestly rather than guessed at | A manifest index (no `artifactType`, no `config`, no layers) | Row carries repository, tag, digest and a `multi-arch` marker, with no fabricated arch or size | The row invents a size or an architecture, or the index raises | Deterministic (`respx` fixture) | 100% |
| **Guardrail — the backend never pulls model weights** | A full walk against the live four-repo catalog | No request for any `modelkit.model.v1.tar` or `modelpart` layer; `embark.json` never fetched or parsed; exactly `1 + R + T + B` registry-path requests | Any request whose digest matches a weights or `embark.json` layer | Deterministic (`respx` route call counts) | 100% |
| **Guardrail — an oversized blob is refused, not buffered** | A blob response body of 1,114,112 bytes (cap + 64 KiB) | `FetchError` raised while streaming; the whole body is never materialized; `MAX_BLOB_BYTES == 1_048_576` | The body is read whole and then measured, or the cap constant is silently raised | Deterministic (`test_registry_client.py`) | 100% |
| **Guardrail — the store survives eight concurrent writers** | Eight concurrent digest writes through the real store path under `asyncio.to_thread` | All eight rows present on read-back; every worker opened and closed its own connection | A module-level or otherwise shared connection; a read-only concurrency test standing in for this row | Deterministic (`test_registry_store.py`) | 100% |
| **Guardrail — no credential reaches the browser** | A rendered `/api/registry` payload and the served `index.html` | Neither contains the registry password, the Vault path's value, nor an `Authorization` header value | Any credential value present in the response body or the static assets | Deterministic (`test_main.py`) | 100% |
| **Guardrail — the registry view stays behind oauth2-proxy** | The rendered `oauth2-proxy.hcl` env block | No `OAUTH2_PROXY_SKIP_AUTH_ROUTES`, `SKIP_AUTH_REGEX` or `SKIP_AUTH_PREFLIGHT`; `/api/registry` is a guarded upstream | Any skip-auth key present, or `/api/registry` reachable unauthenticated | Deterministic (`scripts/check_oauth2_proxy_guard.py`) | 100% |
| **Guardrail — dash's resource reservations do not move** | `deployments/applications/services/dash.hcl` after the change | Frontend `cpu = 50` / `memory = 32`; backend `cpu = 200` / `memory = 128`, all unchanged | Either reservation raised to make the feature fit | Deterministic (adversarial hand-off check) | 100% |
| A registry outage degrades the tab instead of the page | Registry unreachable during a walk | Route returns 200 with an error payload the tab renders; `/api/status` and the rest of dash keep working | The route 500s, or the whole page fails to render | Deterministic (`test_main.py`) | 100% |
| A restart costs no re-fetching | Restart the backend task with a populated `dash_data` volume | Zero blob fetches and zero markdown renders on first request; cards served from SQLite | A restart that re-walks blobs or re-renders any card | Deterministic (`test_registry_store.py`) | 100% |
| The shipped tab looks and behaves as the approved mockup | The deployed page, signed in, both tabs exercised | Tab strip, kit cards with the to-scale layer bar, modal order card → layers → commands, tab keyboard nav, modal backdrop close, copy buttons, theme toggle — all as `assets/registry-mockup.html`. **This row does NOT measure: that the browser draws the callout, that the empty state appears rather than a blank panel, or that the tab strip switches at all — the repo has no JS or browser test harness (§11 Q4, `declared-proxy`), so those remain a manual check.** | Any listed element or interaction missing or visibly different | Human + rubric (1-5 on fidelity) | 4/5 |
