eval: M2-minio-poc-human-tiers

Definition of Done: with F2 applied and the MinIO job redeployed, a human authenticates to the MinIO console at exactly one of three tiers (Admin / Reader / Writer), gets the S3 access that tier's policy grants, and cannot cross into a tier whose Vault assignment excludes them.

| Behavior | Input | Expected | Scorer | Threshold |
|----------|-------|----------|--------|-----------|
| MinIO exposes three tiered OIDC role providers | `mc admin config get minio identity_openid:ADMIN` (repeat for `:WRITER`, `:READER`) against the redeployed job | All three named configs present; each block's `role_policy` equals its tier policy name (`minio-admin`/`minio-writer`/`minio-reader`) with non-empty `config_url` and `client_id`. Do NOT assert `redirect_uri`: that key is deprecated and `HiddenIfEmpty` on this release, so a correct implementation shows nothing there | deterministic check (`mc admin config get`) | 100% |
| The three tier policies grant their intended action sets | `mc admin policy info minio minio-admin` (repeat for `minio-writer`, `minio-reader`) | `minio-admin` = full access; `minio-writer` = put/get/list (plus accepted multipart actions); `minio-reader` = get/list and no `s3:PutObject`; no "policy does not exist" and zero exit | deterministic check (`mc admin policy info`) | 100% |
| Each Vault OIDC client (created by this ticket, not F2) is bound to exactly its own tier's assignment | `vault read identity/oidc/client/minio-admin` and `vault read identity/oidc/assignment/minio-admin` (repeat for `minio-writer`, `minio-reader`) | Each client returns `client_id` and `redirect_uris` equal to `["https://minio.lab.orangecluster.nl/oauth_callback"]` (the one shared callback, identical across all three tiers), plus an `assignments` entry for its own tier; each assignment lists only that tier's group id (`app-minio-admins`/`app-minio-writers`/`app-minio-readers`) in `group_ids`, an empty `entity_ids`, and never another tier's group | deterministic check (`vault read identity/oidc/client` + assignment) | 100% |
| A reader authenticates to the Reader tier and gets read-only S3 | Same check as the row below's Reader sub-part. *(No independent scripted mechanism exists: `aws` is not on PATH and `mc` has no OIDC/web-identity flow in this environment, so a full authorize-to-S3-session round trip cannot be scripted here the way the cross-tier-deny row scripts a bare authorize call.)* | Verified via the browser close-out below: reader session is read-only (list/get succeed, put/upload denied), confined to the reader tier | human + rubric (see row below, reader sub-part) | 4/5 |
