# Decisions

Append-only records of choices that rejected a real alternative, never written over.

* [ADR 0001: Durable knowledge is kept in a validated OKF bundle, not in docs/ or AGENTS.md](0001-durable-knowledge-lives-in-an-okf-bundle.md) - Why this repository keeps its decisions, lessons and unbuilt proposals in .okf/ with checked frontmatter and an append-only decisions directory, rather than as more pages in docs/ or more paragraphs in AGENTS.md.
* [ADR 0002: docs/ is sorted by reader intent, and holds only pages for people who use the cluster](0002-docs-are-sorted-by-reader-intent.md) - docs/ gains how-to/, reference/ and explanation/, one folder per Diátaxis type. Mixed pages are split by section with their wording kept, and material for people working on the repository moves to .okf/.
* [ADR 0003: Lab names resolve from public DNS, not a local resolver](0003-lab-names-resolve-from-public-dns.md) - Names under lab.orangecluster.nl are public A records pointing at a private address, and the dnsmasq split-horizon resolver on firebat was removed. This trades a little disclosure for household DNS that does not depend on the cluster.
* [ADR 0004: The .consul zone is not forwarded to Consul](0004-consul-names-are-not-forwarded.md) - LAN clients cannot resolve .consul names, and that stays so. Forwarding the zone would hand out container bridge addresses that connect to nothing, so clients use node addresses and ports instead.
* [ADR 0005: Short-lived Postgres credentials come from Vault's database secrets engine, not PostgreSQL 18 native OAuth](0005-postgres-credentials-come-from-vaults-database-engine.md) - The S2 spike proved Path A, Vault minting a Postgres user per lease, against memex's real tables, and recommended R3 roll it out. Path B, PostgreSQL 18 OAuth, was rejected because no usable validator exists for Vault or Nomad tokens.
* [ADR 0006: Each job that mints database credentials gets its own Vault JWT role, and the shared nomad-workloads policy is not widened](0006-each-converted-job-gets-its-own-vault-jwt-role.md) - A job reading database/creds/* names a dedicated JWT role whose policy also carries its KV grants. Widening nomad-workloads was one line of Ansible but would let every workload mint database users.
* [ADR 0007: OpenViking's static MinIO key carries no claim-mode policy](0007-openviking-static-key-has-no-claim-policy.md) - OpenViking's S3 config cannot take short-lived credentials, so its job reads the openviking MinIO user's static key from Vault. No minio_iam_policy named openviking sits beside it, because one would read as live while granting nothing.
* [ADR 0008: OpenViking's rerank goes through Bifrost, not straight to embark](0008-openviking-rerank-goes-through-bifrost.md) - OpenViking reranks through Bifrost like every other model call, which meant upgrading Bifrost to 2.0.0 so it accepts bare-string documents. Pointing rerank at embark directly would have worked without the upgrade and was rejected.
* [ADR 0009: OpenViking has no browser surface; Web Studio is unmounted and its proxy removed](0009-openviking-has-no-browser-surface.md) - oauth2-proxy-openviking and Web Studio are gone because Studio cannot collect a credential under oidc. Studio is unmounted rather than left up without its proxy, and the hostname now serves ov-dash.
* [ADR 0010: Vault generates each person's TOTP QR, and self-enrollment stays off](0010-vault-generates-each-totp-qr.md) - Enrollment is an admin-generate run per person through just mfa_enroll. enable_self_enrollment was rejected because no Terraform provider exposes it and it guards a password stolen after enrollment only.
* [ADR 0011: Login MFA is enforced on the userpass mount accessor, not on an entity or a mount type](0011-login-mfa-enforcement-names-the-userpass-mount.md) - The TOTP login enforcement names vault_auth_backend.userpass.accessor. Naming the operator entity challenged the ov-dash trade on jwt-lab, and naming the mount type would have widened it to jwt-nomad.
* [ADR 0012: TOTP enrollment has no app on dash](0012-no-mfa-enrollment-app-on-dash.md) - Nobody builds an enrollment page behind SSO, because an unenrolled person cannot complete the Vault login that reaching dash requires. Vault's own UI is the GUI after enrollment.
* [ADR 0013: The devcontainer shares its uv and prek caches with loop-harness by volume name](0013-devcontainer-shares-caches-with-loop-harness.md) - The localstack devcontainer mounts the loop-harness-uv-cache and loop-harness-prek-cache volumes, so both containers fill one cache. Hooks run through prek instead of pre-commit. Renaming a volume on either side silently ends the sharing.
- [ADR 0014: Keep project knowledge in an OKF bundle](0014-keep-project-knowledge-in-an-okf-bundle.md): Project knowledge lives in an OKF bundle in .okf/, next to the code, not in a wiki or README notes. (superseded by ADR 0001)
- [ADR 0015: loopctl owns the pre-commit hook and chains prek behind it](0015-loopctl-owns-the-pre-commit-hook-and-chains-prek-behind-it.md): The loop harness's commit gate owns .git/hooks/pre-commit and runs prek's hook as pre-commit.local, and the devcontainer installs a pinned loopctl so the gate survives a rebuild.
- [ADR 0016: SeaweedFS replaces MinIO for object storage](0016-seaweedfs-replaces-minio.md): MinIO is end of life and its published image no longer downloads, so the cluster's S3 store moves to a single-node SeaweedFS on orangepi4a, over Garage and over running MinIO built from source.
- [ADR 0017: SeaweedFS keyless access uses one trust-bound role per job](0017-seaweedfs-keyless-roles-bound-per-job.md): Keyless jobs reach SeaweedFS by trading their Nomad workload identity for a role whose trust policy names that job's nomad_job_id and sub, over SeaweedFS's claim mode, which splits the claim on commas and handed a job named evil,tempo tempo's policy.
- [ADR 0018: MinIO is removed without destroying its data](0018-remove-minio.md): Once every consumer had moved to SeaweedFS, the MinIO job, its routes, monitoring and keys were deleted and its Terraform resources dropped from state with destroy = false, keeping the minio_data volume for the operator. Destroying the volume in the same step was rejected because it cannot be undone.
- [ADR 0019: Hermes's OpenViking provider is built into the image](0019-hermes-openviking-plugin-built-into-the-image.md): From hermes-agent v0.22 the OpenViking memory provider is a catalog plugin, so the Hermes image copies it in at build time, pinned by commit, over letting Hermes install it from GitHub at first start.
- [ADR 0020: Agents use OpenViking through tools only](0020-agents-use-openviking-through-tools-only.md): Hermes and Claude Code read and write OpenViking only when the user or a skill asks, through tools, over automatic recall and capture on every turn.
- [ADR 0021: OpenViking starts over on a v2 store](0021-openviking-starts-over-on-a-v2-store.md): OpenViking moves to a new bucket, schema and workspace volume with one lab/jasper identity, and the old store stays as a read-only backup because its key is moved off it.
- [ADR 0022: OpenViking carry-over copies storage and re-indexes](0022-openviking-carry-over-copies-storage-and-re-indexes.md): The trees kept from the old OpenViking store are copied key for key into the new bucket and re-indexed there, blog-scraper merged into blogs, with no old instance running.
- [ADR 0023: Hermes saves from a skill-owned map of roots](0023-hermes-saves-from-a-skill-owned-map-of-roots.md): The save-to-openviking skill finds a folder from a map of resource roots that it owns, over walking the live tree on each save and over a job that rebuilds the map.
- [ADR 0024: The devcontainer reads the host OpenViking login through a read-only mount](0024-the-devcontainer-reads-the-host-openviking-login-through-a-read-only-mount.md): The devcontainer bind-mounts the host ~/.openviking read-only, so ovsync and ov authenticate with the host login and the token is renewed on the host.
- [ADR 0025: The agent guidelines stay in AGENTS.md](0025-the-agent-guidelines-stay-in-agents-md.md): After aim goes, the behavioral guidelines aim wrote into AGENTS.md stay there as plain text instead of moving into a rule.
- [ADR 0026: Repo docs reach OpenViking through a webhook receiver, a JetStream queue and a consumer](0026-repo-docs-reach-openviking-through-a-webhook-receiver-a-jetstream-queue-and-a-consumer.md): Filer events on the ov-sync bucket go from a loopback receiver inside the seaweedfs job, through a JetStream stream, to a consumer on radxa that writes and deletes in OpenViking.
- [ADR 0027: CI reaches the lab through a public lab-auth action and per-caller Vault roles](0027-ci-reaches-the-lab-through-a-public-lab-auth-action-and-per-caller-vault-roles.md): A composite action in this repo joins a job to the tailnet as tag:ci through a Tailscale federated identity and logs it in to Vault with its GitHub OIDC token, and one jwt-github role per allowed workflow decides who gets a token.
- [ADR 0028: CI syncs repo folders to a shared ov-sync bucket with a manifest and a Vault identity token swapped at SeaweedFS STS](0028-ci-syncs-repo-folders-to-ov-sync-with-a-manifest-and-a-vault-identity-token.md): The openviking-sync action writes git-tracked folders to the caller's own prefix of ov-sync, tracks what it wrote in a manifest object, and gets S3 credentials by swapping a Vault identity token at SeaweedFS STS.
- [ADR 0029: Bifrost routes by complexity for one virtual key and adds Jev](0029-bifrost-routes-by-complexity-for-one-virtual-key-and-adds-jev.md): Only the router key goes through the clef Complexity Router, with an explicit model list, and Jev is a typesafe provider with its default base URL.
- [ADR 0030: ov-sync stores images in OpenViking per-file folders](0030-ov-sync-stores-images-in-openviking-per-file-folders.md): Images reach OpenViking through temp_upload and add resource at D/name/name, its native layout, instead of an exact URI through a temp folder and fs/mv.
- [ADR 0031: The lab-auth action picks the Tailscale identity from the OIDC subject format](0031-the-lab-auth-action-picks-the-tailscale-identity-from-the-oidc-subject-format.md): The lab-auth action reads the job OIDC sub and uses the immutable-subject Tailscale identity for repositories created after 2026-07-15 and the original identity otherwise, so no caller passes Tailscale inputs.
- [ADR 0032: Summarize OpenViking content with inkling-2-small](0032-summarize-openviking-content-with-inkling-2-small.md): OpenViking writes image and text summaries with ollama/inkling-2-small, thinking off, instead of gemini-3.5-flash-lite or gemma4:31b.
- [ADR 0033: NetworkManager nodes get public fallback resolvers](0033-networkmanager-nodes-get-public-fallback-resolvers.md): radxa and orange_pi_4a list the router, then 1.1.1.1 and 9.9.9.9, through a NetworkManager global-DNS drop-in, so one dropped query no longer fails a lookup.
- [ADR 0034: Local ovsq syncs use a keyless operator STS role, not a static key](0034-local-ovsq-syncs-use-a-keyless-operator-sts-role-not-a-static-key.md): The operator laptop writes ov-sync/JasperHG90/local/ with 15-minute STS credentials minted from their Vault session, not with the static S3 key ovsq upstream prescribes.
