# How to log in to Vault

## Introduction

Log in to Vault as yourself, with the `userpass` backend, so your token
carries an identity. Do this before any task gated on identity: group
membership, and therefore OIDC assignment, resolves through the entity.

Two-factor auth is not enforced on this login yet.
[How to roll out Vault login MFA](roll-out-vault-login-mfa.md) has the TOTP
rollout, the enrollment recipes, and the order that avoids a lockout.

## Prerequisites

- The Vault CLI, and a network route to `vault.lab.orangecluster.nl`.
- A token that can read `secret/default/vault/operator`, to fetch the
  password.

## Directions

### Step 1: Read the password

The password is generated by Terraform and never appears in the repo or in
`vars/prod.tfvars`. Read it from Vault:

```
vault kv get secret/default/vault/operator
```

### Step 2: Log in

```
export VAULT_ADDR=https://vault.lab.orangecluster.nl
vault login -method=userpass username=operator
```

### Step 3: Confirm the login produced an identity

Confirm the login produced an identity, not just a token:

```
vault token lookup -format=json | jq -r '.data.entity_id'
```

A non-empty `entity_id` is the point of the whole userpass backend. Group
membership, and therefore OIDC assignment, resolves through the entity. The
root token from bootstrap has an empty `entity_id`, so it cannot exercise
anything gated on identity, which is why it is not a substitute for logging
in.
